JOKAngel Crystal — Advised Website Plan
Source: PLAN.txt, reconciled with /resources.
Status: spec only. Do not treat this as permission to invent missing copy, prices, or SKUs.

This file replaces PLAN.txt as the build spec. Keep PLAN.txt as the original brief.


============================================================
1. Goal and non-goals
============================================================

Goal
- Static showcase site for JOKAngel Crystal, a Hong Kong crystals and accessories brand.
- Pieces are unique. Visitors browse photos, read light brand/story content, see partner services, and book an appointment on WhatsApp. No prices on the site.

Non-goals for v1
- No prices, cart, checkout, payments, accounts, or inventory sync.
- No CMS, no runtime database, no Next.js middleware (incompatible with static export).
- No Cursor update-skills until the site data shape is stable (Phase 2).
- Do not publish empty categories, leftover installer/PPTX files, or AI watermarks.


============================================================
2. Locked decisions
============================================================

Brand
- Display name: JOKAngel Crystal
- Tone: refined, calm, premium. Not playful, not neon e-commerce.

Languages
- zh-Hant (default), zh-Hans, en.
- Cookie-based, not routing-based. URLs never include a locale segment.
- UI chrome, nav, buttons, and empty states are translated on the client from the cookie.
- Product names and descriptions: Traditional Chinese is source of truth. Provide zh-Hans and en fields; if a translation is missing, fall back to zh-Hant. Do not auto-machine-translate in the build.
- Do not sniff navigator.language. Default stays Traditional Chinese until the visitor picks another language.

Tech
- Next.js App Router.
- output: 'export' for GitHub Pages.
- trailingSlash: true.
- TypeScript + CSS modules or Tailwind. Pick one styling system and keep it.
- Images: next/image with unoptimized: true (required for static export).
- i18n: one URL per page. Locale lives in a cookie (and localStorage backup).
  Example: /products/cinnabar/ stays /products/cinnabar/ in every language.
- No middleware, no locale generateStaticParams, no /zh-Hant root redirect.
  Static export cannot read cookies on the server; the first HTML is always zh-Hant, then the client applies the saved locale before paint (see section 10).
- basePath: '' if hosted at <user>.github.io. If hosted at <user>.github.io/<repo>, set basePath to '/<repo>'.
- File-driven content: JSON/MD in /content is imported at build time and turned into static pages (“Generate static pages from JSON”). URLs are not fetched from an API.

Commerce
- Showcase + WhatsApp 查詢／訂購 only. No price anywhere in the UI.
- WhatsApp: +852 68888464
- Appointment link format:
  https://wa.me/85268888464?text=<urlencoded 預約查詢 + product name + url>
- Filenames that contain $ amounts are only for grouping photos. Do not import or render those numbers.

Corrections from PLAN.txt
- 珠砂 → 朱砂.
- Add resource categories that already exist: 舒俱萊, 金運石.
- Product detail pages are required.
- Blog is file-driven under /blog/[category]/[slug]. Home teasers use the first two categories: story, cases.

10. i18n (cookie) and GitHub Pages notes
============================================================

Why cookie, not routes
- Static GitHub Pages has no server to read a cookie and render a locale.
- Locale prefixes would triple every static path and break the “one URL per product” share link.
- Cookie + client provider keeps /products/cinnabar/z001-raw-cinnabar/ stable.

Storage
- Cookie name: jokangel_locale
- Values: zh-Hant | zh-Hans | en
- Default: zh-Hant
- Attributes: Path=/; Max-Age=34560000; SameSite=Lax
- Backup: localStorage.jokangel_locale (same values)
- Read order: cookie → localStorage → zh-Hant
- Write the cookie only when the visitor picks a language. Do not set it on first paint of the default.
- Do not auto-detect browser language.

Anti-FOUC
- Static HTML is generated in zh-Hant.
- Put a tiny blocking script in <head> that reads the cookie/localStorage, sets document.documentElement.lang and data-locale, and adds a class (e.g. locale-ready) so the first painted strings match the saved locale after hydration.
- LocaleProvider hydrates from the same source. LanguageSwitcher updates cookie, localStorage, lang, and React state. No navigation.

Optional one-shot
- ?lang=en (or zh-Hans / zh-Hant) may write the cookie then drop the query. This is for a shared “open in English” link, not the primary mechanism.

Content split
- Dictionaries in content/i18n cover chrome only.
- Product/category/blog strings stay in their own files and are selected by the active locale on the client.

Tradeoff
- EN and zh-Hans are not separate crawlable URLs. Acceptable for a catalog-plus-WhatsApp site. If SEO for English later matters, add hreflang or a route mode then — do not mix both in v1.

GitHub Pages
- Static export: no ISR, no middleware, no server actions.
- Deploy the out/ folder. Add .nojekyll.
- If the repo is project-pages (not a user/org site), set basePath and assetPrefix.
